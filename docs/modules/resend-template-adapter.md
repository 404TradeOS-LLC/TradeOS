# TradeOS Resend dashboard template adapter

## Current production behavior

`app/modules/email/service.ts` sends password resets, dispatcher/technician invitations, and single-use customer-portal access links using the existing TradeOS-branded HTML and plain-text renderer. **Inline rendering remains the default**; this branch does not change any live environment variable or deploy an updated backend.

## Optional provider-hosted templates

Set server-only `RESEND_TEMPLATE_MODE=dashboard` in an approved isolated staging API environment to opt in to the three verified published Resend templates:

| TradeOS email | Resend template alias | Required variables |
| --- | --- | --- |
| Password reset | `tradeos-password-reset` | `RESET_URL`, `EXPIRES_AT` |
| Team invitation | `tradeos-team-invitation` | `ROLE`, `INVITE_URL`, `EXPIRES_AT` |
| Customer portal access | `tradeos-customer-portal-access` | `PORTAL_URL`, `EXPIRES_AT` |

All URLs are generated by the backend from `APP_BASE_URL` with URL-encoded opaque tokens. The existing sender setting `EMAIL_FROM` remains in use and must refer to a verified sending address (normally `TradeOS <hello@404tradeos.com>`). The Resend API credential remains server-only.

**Opt-in behavior:** TradeOS posts `{ from, to, template: { id, variables } }` with the original deterministic idempotency key. It does not include parallel `html`/`text`/`subject` fields because the published templates own those values. An unset or unrecognized mode uses the current inline sender. A provider rejection fails closed with the existing sanitized error; the adapter never retries as inline mail, avoiding potential double delivery.

**Deployment transition risk:** A token-specific idempotency key is intentionally unchanged across modes. Resend can return `409 invalid_idempotent_request` if the same key is reused with a changed request body within its idempotency window. Do not switch modes in the middle of an in-flight token delivery or retry campaign.

## Protected acceptance plan

1. Verify exact-head CI, independent code review, and matching API/web deployment source SHA in protected staging.
2. Confirm the account's domain and three template aliases are published. Verify Vercel backend Preview values for `RESEND_API_KEY`, `EMAIL_FROM`, `APP_BASE_URL`, and `RESEND_TEMPLATE_MODE` without exposing their secrets.
3. Run provider/API contract tests with a synthetic recipient: one example each for reset, invitation, and customer portal, using a staging-only token, and inspect rendered HTML and plain-text content for the right URL and expiration.
4. Check invalid link, expired link, replay/idempotency, and cross-tenant denial behavior without using real customer records.
5. Keep production in inline mode until staged acceptance, application owner review, release approval, and a rollback plan are recorded. Do not enable a mode switch as an implicit part of merging this branch.

## Boundaries

This adapter does not configure webhook event storage, email suppression or bounce handling; those belong to separate reviewed work. A direct Resend-to-mailbox smoke test does not certify the deployed TradeOS API's environment or its invitation and portal flows. Google Workspace incoming MX/SPF/DKIM records are unaffected.
