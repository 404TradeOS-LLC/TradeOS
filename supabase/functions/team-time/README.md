# TradeOS Team & Time — source-controlled staging baseline

- Source: `index.ts` is an exact copy of the deployed Staging Edge Function v6 on 2026-10-30, preceded by a short source-control safety header. The live metadata reported bundle SHA-256 `c424de8ea25d0388c43793fda5b0063ed87eeb0bef222153d0498d317a2c8c19`. That is a **deployed bundle identifier**, not a claim that the repository file hashes to the same bytes.
- Scope: nonproduction **staging only**. `TEAM_TIME_ENABLED` and `TEAM_TIME_SUPABASE_PROJECT_REF` must match the staging project. The production UI remains disabled.
- Database prerequisites: tracked Prisma equivalents `20261030004500_team_time_foundation`, `20261030005500_team_time_integrity`, then `20261030010000_force_team_time_rls`. Staging originally applied Supabase versions `20260924145928` and `20260924150458`; the new Prisma equivalents use `CREATE TABLE IF NOT EXISTS` and do not drop data.
- **Critical threat model:** the function authenticates the Supabase bearer JWT then performs PostgREST queries with a server-only **service-role secret**, which bypasses PostgreSQL RLS even with `FORCE`. Thus **every user, membership, organization, job-assignment and shift authorization check in this function is security-critical**. The FORCE migration hardens the database owner posture and guarantees a controlled schema baseline, but it is not a substitute for those checks.
- No `anon` or `authenticated` direct table grants are added by these migrations. A revoked/invalid Supabase session, cross-organization request, unassigned job, foreign shift or non-supervisor review request must fail before mutation. The `app/tests/team-time-edge-auth.test.ts` tests run the actual source with synthetic auth and a fake service-role transport.
- The snapshot is not an approval to deploy the function again or enable Team & Time in Production. Before changing it, reconcile its contents against the staging version; run the security tests, staging deployment verification, and reviewed protected environment gates. Never expose the service secret in browser scripts or test logs.
- For a future non-bypass database authorization layer, design reviewed `TO authenticated` policies with explicit tenant claims and access checks and verify that Edge Function queries truly use that identity. Never assume FORCE alone removes `BYPASSRLS`.
